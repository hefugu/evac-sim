# 廊下の煙先端モデル

`sim/js/simulation/corridor-smoke.js` は、既存の保存量ベース煙モデルに廊下専用の移流則を追加する。長い廊下を瞬時に一様混合された部屋として扱わず、温度と煙層厚さに応じた重力流によって隣接セルへ煙を運ぶ。CFDソルバ、CFASTそのもの、実火災の絶対予測、法令適合判定の実装ではなく、避難経路とシナリオの比較用 reduced-order model である。

## 根拠と近似

[NIST SP 1026r1, §3.4.4 (printed pp. 37–41)](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.1026r1.pdf) は、廊下における煙の到達遅れと、層厚・温度差に依存する重力流という扱いを説明している。本実装はこの物理的考え方に基づく局所的な閉包則であり、同資料のFDS由来の温度減衰相関やCFAST全体を再現してはいない。

使用する式は以下である。

\[
g'=g\frac{T_u-T_a}{T_u},\qquad u_f=Fr\sqrt{g'h}
\]

- `g'`: 低減重力加速度 [m/s²]。理想気体の密度比から求める。
- `g`: 重力加速度、既定 9.81 m/s²。
- `T_u`, `T_a`: 上層煙・周囲空気の絶対温度 [K]。入力の °C に273.15を加える。
- `h`: セル内の上層煙厚さ [m]。保存している高温気体体積 `V` [m³] / セル面積 [m²]。
- `Fr`: 無次元Froude係数、既定0.7。シナリオで変更できる近似係数であり、当該建物について検証済みの値ではない。
- `u_f`: 煙先端の局所速度 [m/s]。既定の数値上限は5 m/s。温度差ゼロでは浮力による移流速度もゼロ。

本式の温度差の分母は `T_u` であり、NIST資料に記載された入口相関をそのまま複製しているわけではない。低温度差では両表現は近づくが、高温度差で差があるため、Froude係数と合わせて感度解析対象とする。

上層温度は既存の保存量から `T_u [°C] = T_a + E/(ρ c_p V)` で計算する。`E` は超過顕熱 [kJ]、`ρ` は既存モデルの一定代表密度 [kg/m³]、`c_p` は [kJ/(kg·K)]。局所速度に理想気体の密度比を用いる一方、輸送する熱容量には既存の一定密度近似を維持している。

## 保存量への結合

移流量の上限は `V_out = V (1 - exp(-u_f Δt / Δx))` [m³] とし、全流出先合計を最大 `0.3 V` と既存CFL係数で制限する。さらに `min(1, Σ max(0,h-h_neighbor)/h)` を乗じ、層厚が等しくなるにつれて移流を連続的にゼロへ近づける。これは陽的移流を安定させ、微小な層厚差で流れが反転し続けることを防ぐ局所近似である。層厚が薄い隣接セルへ層厚差に比例して分配する。領域内部の横断方向混合は既存モデルが担当する。

廊下セルでは通常の天井ジェット移流を置き換える。算出した流量は既存 `smoke3d.js` の同一フラックス処理に渡し、体積・soot質量 [kg]・CO質量 [kg]・超過顕熱 [kJ] を移動元から減らし、移動先に同量加える。専用モデルが煙を生成したり、濃度を上書きしたりすることはない。既存の火源注入・混合・容量処理・階段移動・換気・沈着を継続するため、soot/COの損失勘定は共有される。

`floor.corridorSmoke.segments` は同じ保存量から診断した次の量を公開する。

| フィールド | 意味・単位 |
| --- | --- |
| `frontPositionMeters` | 軸の小さい側の領域境界から測った最大側煙先端 [m] |
| `frontMinPositionMeters` | 同じ基準による最小側煙先端 [m] |
| `fronts` | 両方向の先端位置と局所速度（途中火源・階段流入にも対応） |
| `frontVelocityMps` | 両端の局所重力流速度の最大値 [m/s] |
| `upperLayerDepthMeters` | 領域面積で平均した煙層厚さ [m] |
| `upperLayerTemperatureC` | 保存量から求めた領域体積平均温度 [°C] |

先端は層厚が既定0.01 m以上のセル端として観測するため、位置分解能はセルサイズに依存する。独立した鋭い界面を強制してはいない。既存の乱流混合と数値拡散により先端前方にも微量の煙が存在し得る。壁や閉じた扉を通り抜けることはない。時間刻み依存性は0.1 sと0.05 sのsoot場のL1差で検証する。

## 領域・接続・フォールバック

明示的なシナリオ設定例:

```js
floor.corridorRegions = [{
  id: "east-hall",
  axis: "x", // x または y
  cells: Array.from({ length: 30 }, (_, cx) => ({ cx, cy: 7 }))
}];
```

セルの `corridor: true` または `regionType: "corridor"` でも指定できる。任意で `corridorId` と `corridorAxis` を指定する。実行中にセルの領域指定を変える場合は `floor.corridorRevision` を増加させる。`floor.corridorRegions` の変更と構造・扉の変更はキャッシュへ反映する。

既定の自動判別は、直線・一定幅で、長さ6 m以上、幅4 m以下、長さ/幅3以上の帯状領域だけを選ぶ。これらは建築上の廊下を厳密に識別する基準ではなく、説明可能な保守的形状ヒューリスティックである。明示領域はこの寸法条件を上書きできるが、壁・閉鎖扉は除外する。長さ2セル未満の断片、幅が変わる部分、曲がり角、分岐、広い部屋は通常のセルモデルへ戻る。複雑な学校平面では明示的な領域設定を推奨する。

軸方向端部と側方の開口は、実際に隣接する通過可能セルにだけ保存量を渡す。開いた扉・別廊下との接続・通常の部屋への流出も同じ処理を使う。階段で運ばれた煙は、接続先セルに既に存在する保存量として次の廊下ステップに入り、火源のない上階でも重力流を生む。階段流量自体は従来の共有モデルが計算する。

扉の `doorOpen: false`、`doorClosed: true` または `doorState: "closed"` は煙の通過を禁止する。状態を持たない旧形式の `door: true` は後方互換のため開いているとみなす。扉下隙間などの漏れをこの流路では表現しない。

| option | 既定値 | 意味 |
| --- | ---: | --- |
| `corridorModelEnabled` | true | 廊下移流を使用 |
| `corridorAutoDetect` | true | 帯状領域を自動判別 |
| `corridorMinLengthMeters` | 6 | 自動判別の最小長さ [m] |
| `corridorMaxWidthMeters` | 4 | 自動判別の最大幅 [m] |
| `corridorMinAspectRatio` | 3 | 自動判別の最小縦横比 |
| `corridorFroudeNumber` | 0.7 | 局所重力流の近似係数 |
| `corridorMaxFrontVelocityMps` | 5 | 速度の数値上限 [m/s] |
| `corridorMaxTransferFraction` | 0.3 | 1サブステップ当たり流出体積率の上限 |
| `corridorFrontDepthThresholdMeters` | 0.01 | 先端診断の層厚閾値 [m] |

`corridorModelEnabled: false` で従来のセル移流に完全に戻せる。リセット時には共有煙状態と廊下診断を初期化する。3D側で独立した煙計算を進めない。

## 検証の範囲

`tests/corridor-smoke.test.mjs` は、数式・長廊下/広い部屋の分類・壁/扉遮断・開口連成・階段流入による開始・分岐予算・対称性・時間刻み収束・soot/CO/熱/体積保存を確認する。これは実装の物理整合性の確認であり、実験との建物別妥当性検証を代替しない。
