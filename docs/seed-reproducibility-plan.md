# Issue #2: seed再現性の実装方針

対象: https://github.com/hefugu/evac-sim/issues/2

この文書は実装計画。今回の階別セルサイズ修正にはPRNGの導入を含めない。

## 再現の単位

同じモデル版、マップ・階別寸法・階段リンク、FDSデータ、設定、seed、固定物理刻みを与えたとき、避難者別結果と集計結果を再現する。描画FPSや表示階の切替が乱数列や物理ステップ数に影響しないようにする。異なるブラウザエンジン間の浮動小数点のビット一致は別途検証が必要。

## 実装順序

1. `simulation/random.js` に仕様とバージョンを固定した32-bit PRNGと文字列seedのハッシュを追加する。既知の入力列に対する出力ベクトルをテストし、状態の保存・復元を可能にする。seed=0も有効値として扱う。
2. simulation stateに入力baseSeed、正規化seed、runIndex、runSeed、PRNG状態・アルゴリズム版を保持する。初期配置前に初期化し、やり直しでは同じseedから再生成する。停止・再開では巻き戻さない。
3. `core.js` のタイプ・配置・速度差・パニック・経路ノイズの直接 `Math.random()` 呼出しを置換する。`sampleFdsEvacPerson`、`stepPedestrianDynamics`、火災の `random` 引数にも注入する。描画用乱数は別系統に分ける。物理側の直接呼出しが残っていないことを確認する。
4. 設定UIとプリセット保存にseedを追加する。「ランダムseed」モードは開始時に一度seedを生成し、採用した値を表示・保存する。過去のプリセット読込時の既定動作も明示する。
5. MCのrunSeedを `hash(version, baseSeed, runIndex)` のように試行番号から独立に導出する。前回の乱数消費数に依存させず、中断後の再実行や特定runの再現を可能にする。試行間ではマップ、火災、煙、階段待ち行列、時計と全乱数状態を初期化する。
6. CSVとsummaryにbaseSeed、runSeed、runIndex、PRNG版、モデル版、物理刻みを記録する。入力設定・マップ・FDSデータの識別情報も併記し、出力から再実行条件を特定できるようにする。

## 受入テスト

- 単独試行を同じ入力・seedで2回実行し、全避難者の終了状態・時刻と集計を比較する。
- MC100回を2回実行し、順序付き結果を比較する。途中のrunだけを再実行して一致を確認する。
- 確率的な差が生じるfixtureでseed変更による結果の変化を確認する。
- 表示階、2D/3D、描画頻度を変えても、同じ物理時刻で結果が一致することを確認する。
- Nodeの物理・保存則テストとPlaywright全件を維持する。現状のブラウザテストによる `Math.random` 差し替えを、本実装のseed指定に段階的に置き換える。

将来、人口・歩行・火災を独立した乱数系列にする場合は、系列の分割方法も版管理する。乱数呼出し順の変更は既存seedの結果を変えるため、モデル更新時に再現範囲を明示する。
