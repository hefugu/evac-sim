# evac-sim 移動・避難経路の調査と修正

調査日: 2026-10-09（日本時間）
対象: hefugu/evac-sim main、0646a2df7b67e535c1617393ed884844992f5c8b
公開版: https://evac-sim.vercel.app/sim/

## 結果

ローカルの修正版で単体テスト97件、ブラウザテスト16件が成功。公開版では、追加した「離れた火元」「煙区画の迂回」「狭い曲がり角」の3テストが失敗し、修正版では成功した。GitHubへの変更は修正ブランチとPRで管理する。公開版との比較は修正前のmainを基準にした記録である。

core.js / potential.js / routing.js / stairs3d.js の公開配信内容を取得し、改行を正規化したうえでmainと4ファイルすべて一致することを確認。調査終盤にもorigin/mainが同じコミットであることを確認した。

## 原因と変更

### 1. 火元からの距離を縮める動きの全面禁止

core.jsは安全用の距離場を作る段階と実移動の段階の両方でmoveApproachesFireを使用していた。これは危険範囲の外でも作用するため、十分に離れた出口へ向かうだけで進行不能になる。

危険範囲を避ける経路網は維持し、その外側で火元に近づく方向まで禁じる処理を外した。すでに危険範囲内にいる場合は、routing.jsに既存のextendPotentialIntoFireAvoidanceZoneを接続し、安全側へ出る勾配を与える。安全側から危険範囲への再進入は通常経路で禁止する。火元の近くで現在セルが通行禁止になった人については、出口へ到達できる合法な隣接セルがあればそこへ脱出できるようにした。到達可能なセルが隣接しない場合は、未完了として保持する。

### 2. 煙・熱を一歩先の評価だけで避けていた

従来の距離場は歩行距離中心で、煙やFDS由来のCO・温度等は隣接候補の評価だけに使用していた。そのため局所的に煙を避けても、区画全体を回り込む方向が分からず停止する。

出口を起点にしたDijkstra法で、既存の危険度ペナルティを経路全体に積算する。実際の火炎・既存の火災通行禁止条件は距離場でも通れない。1.5シミュレーション秒ごとの再計画で、煙・FDS・階段待ちの変化を反映する。出口を切り替えない場合にも古い距離場を保持し続けないよう更新した。煙・火災の物理計算や曝露の式は変更していない。

### 3. 距離場と移動の壁判定が不一致

potential.jsは斜めの角抜けを禁止していたが、core.jsの隣接候補判定では同じ検査をしていなかった。救助移動では移動先のwalkable検査も欠けていた。

grid-movement.jsで線分が横切る全セルと角の両側を検査する。通常移動と救助移動で使用する。壁角の手前では現在セルの中心まで進んでから曲がるため、セルを丸めるだけの処理による壁抜けを防ぐ。混雑時の巻戻しもセル中心への瞬間移動ではなく直前の連続座標に戻す。

### 4. 距離場より局所評価が勝ち、止まる

混雑、通過履歴、向き、空気の改善がないclear-air候補への加点などが出口方向への移動を妨げ得た。進める下降方向があるときはそれを候補群として優先し、その中で局所条件を比較する。clear-air加点は実際に改善するときだけに限定した。

候補評価は単純な距離場の落差ではなく「次のセルの値＋そこへ進むコスト」を比較する。これにより、落差が大きいだけの時間のかかる階段が過大評価されることも防ぐ。

### 5. 階段内の人が入口の混雑に残り、到着側は無制限だった

移動中の階段利用者は元階のx/yを保持するが、core.jsがこれを床面の占有人数に算入していた。階段内の利用者を入口セルの密度から除外し、待機中の人は占有したままとした。

stairs3d.jsの到着処理には着地セルの人数・通行可能性の確認がなかった。複数リンクを通じた同時到着にも共通の人数予約を適用し、満員または火災で通れない着地セルでは階段内で待機する。既存の2D/3D用transition表現を維持する。満員の階段では、到着を待つ人とその着地点から出発する人を一対一で入れ替え、上り下りの待ち列による相互停止を防ぐ。通常の入場は全体のFIFO、入れ替え時は進行方向ごとのFIFOを守り、着地人数と階段容量を同時に予約する。火災で通れない着地点にはこの入れ替えを許可しない。

階段秒数を歩行セルのコストと同じ尺度に換算し、待機・移動中人数と容量に基づく待ち時間の概算も経路に加える。24人・2本の階段の試験では、両方を利用して24人全員が避難した。

### 6. 到達不能な人が生成時に消えていた

出口への距離が無限大の場合、spawnAgentsはその人を追加せずcontinueしていた。要請人数より少ない状態で結果を集計してしまう。到達不能者も保持し、観測時間終了時に未完了として記録する。避難完了は選択中の距離場のゼロ判定ではなく、実際の出口セルへの到達で判定する。

### 7. 既存のテストが正常に実行できていなかった

routing.test.mjsのbuildNearestFireDistanceFields / fireDistanceAt / moveApproachesFireのimportが欠けていた。importを修正し、新しい単体テストも既存のnpm test・CI入口に接続した。PlaywrightはPLAYWRIGHT_BASE_URLで公開版に対しても同じ試験を実行できる。

## 3Fサンプルの実測

公開版の「3Fサンプル読込」をブラウザで実行した結果:

- 150×200セル、3フロア枠、画像があるのは3Fのみ。
- 階段セル640、連結した緑領域は5か所。
- 階段リンク0、出口0。

緑領域の抽出は5か所とも行われていた。ただし、緑は階段候補であり、自動的な出口でも下階への接続でもない。現行のモデルは明示されたセル間の階段リンクを使う。下階の画像・接続・出口を設定しないまま、5か所すべてを避難先として利用する構成にはなっていない。今回、下階や出口を推測して自動生成する変更は加えていない。

## 方式選択と検証範囲

既存のグリッドと共有stateを保ち、出口からの距離場、危険度を加えた最短経路、人数制限、階段FIFOを組み合わせた。連続空間のsocial-forceモデルへの置換は行っていない。floor-field型避難モデルと、煙条件にペナルティを与える最短経路は既存文献にある方式である。ただし、今回の係数と階段待ち時間の概算をそれらの実測に較正したわけではない。

- Kirchner / Schadschneider, Simulation of evacuation processes using a bionics-inspired cellular automaton model: https://arxiv.org/abs/cond-mat/0203461
- NIST, Technical references guide for the HAZARD I fire hazard assessment method: https://nvlpubs.nist.gov/nistpubs/Legacy/hb/nisthandbook146v2.pdf

ユーザーが以前使用した開始位置・火元・下階マップ・階段リンク一式は今回提供されていないため、その個別シナリオの再現まで確認したとはしていない。大規模人数の性能、大規模な階段の双方向対向流、物理的な避難時間の妥当性は今回の小規模回帰試験の保証範囲外。通れない出口や満員の着地先で待つこと自体は正常なモデル上の待機であり、停止をすべて強制解消する実装ではない。
